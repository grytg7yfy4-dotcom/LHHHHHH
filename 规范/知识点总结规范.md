# 知识点总结归纳规范 · v1

> 适用：每学完一个系列（B 站课程 / 网课 / 书 / 项目），把知识点做成可以长期复习的静态站点，推到 GitHub Pages。
> 参考实例：[机器学习 15 讲](../ml15/)（15 集 / 124 个知识卡 / 74 道自测 / 速查表 / 学习记录 / 对比吴恩达 / 知识点补充）

---

## 一、成品长什么样

一个系列 = 一个独立目录（如 `series/ml-basics/`），包含 6 类页面：

| 页面 | 内容 | 必须 |
| --- | --- | --- |
| `index.html` 首页 | 系列介绍、统计、模块地图、分集卡片、学习进度 | ✅ |
| `epXX.html` 分集页 | 一句话讲透、5 条要点、6~9 个知识卡、B 站章节跳转、4~5 道自测 | ✅ |
| `cheatsheet.html` 速查表 | 公式 / 指标 / 算法对比 / 选型决策表 / 常见坑 | ✅ |
| `learn-log.html` 学习记录 | 观看时间线、逐集完成状态、累计投入、完结徽章 | ✅ |
| `compare.html` 对比表 | 和参考课程逐知识点对比：已覆盖 / 部分 / 未覆盖 | 推荐 |
| `supplement.html` 知识补充 | 本系列没讲、参考课程里有的知识点 | 推荐 |

设计基调：浅色/深色双主题、蓝紫主色、卡片 + 细边框 + 轻阴影、中文优先、手机可用。

## 二、目录结构

```
series/<slug>/
├─ index.html / epXX.html / cheatsheet.html / learn-log.html / compare.html / supplement.html
├─ assets/
│  ├─ style.css      设计系统（颜色/圆角/卡片/公式/对比表/补充页/响应式）
│  ├─ app.js         渲染器（读 data/*.js，生成全部页面）
│  ├─ figures.js     内联 SVG 图库（静态 + 可交互）
│  └─ favicon.svg
├─ content/          唯一需要手写的地方
│  ├─ meta.json      系列元数据 + 分集目录
│  ├─ ep01.json …    每集内容
│  ├─ cheatsheet.json
│  ├─ compare.json   （可选）
│  ├─ supplement.json（可选）
│  └─ learnlog.json  学习记录
├─ data/             构建产物（course-data.js / learnlog.js / compare.js / supplement.js）
└─ _build/build.py   构建脚本
```

新建：`python 工具/新建知识点系列.py --bvid BVxxxx --slug series/<slug> --title "系列名"`
（生成器自动拉 B 站目录 + 章节，生成 meta 和 ep 骨架）

## 三、内容规范（最重要）

### 3.1 每集必须有的东西

| 项 | 要求 |
| --- | --- |
| `oneLiner` | 40~70 字，一句话说清这集讲什么 |
| `core` | 一句话讲透（可用 **加粗**） |
| `takeaways` | 恰好 5 条，每条 20~50 字 |
| `concepts` | **6~9 个**知识卡，按视频章节顺序 |
| `quiz` | **4~5 道**，覆盖概念辨析 + 易错点 + 小计算 |
| `chapters` | B 站章节（生成器自动拉，用于时间戳跳转） |

### 3.2 每个知识卡的写法

顺序固定，**先直觉后公式**：

1. `h`：标题 4~12 字；
2. `lead`：一句话结论，20~60 字，**加粗关键词**；
3. `body`：2~4 段、200~450 字。第一段「为什么需要它」→ 第二段「原理/公式」→ 第三段「怎么用、和相邻概念的区别」；
4. `formula`（可选）：`{f, n}`，公式用纯文本 + `<sub>/<sup>`，**禁止 LaTeX**；
5. `list` / `table` / `code`（可选）：列要点、做对比、给能跑的代码；
6. `fig` + `figCap`（可选）：最多 2 张/集，必须配说明；
7. `pitfall`：最容易错的一点；
8. `tip`：一句话记忆技巧；
9. `note`（可选）：补充/延伸。

**禁写**：空话（「非常重要」）、无依据的数字、把整段视频逐字稿贴上来、超过 500 字不分段。

### 3.3 图

- 优先「一图解释一个关系」：曲线、树、矩阵、流程、对比；
- 能交互的做交互（拖滑块/点按钮/迭代），参考 `figures.js` 里梯度下降、K-Means、PCA、熵；
- 每张图必须有 `figCap`，说明「这张图在解释什么」；
- 新系列替换 `fig-hero`（首页装饰）和课程地图之外，其余图按需增删。

### 3.4 自测题

- 题干短、能一句话答；答案 1~3 句；`why` 写延伸或易错原因；
- 覆盖：概念辨析（监督 vs 无监督）、公式含义、参数作用、常见坑；
- 不要出「背诵定义」的题，要出「换个场景还懂不懂」的题。

### 3.5 语言风格

- 中文全角标点；术语首次出现给英文（如「泛化 generalization」）；
- 公式里符号统一（`w`/`b`/`θ`/`λ`），同一系列不要混用两套记号；
- 面试导向：每个概念尽量回答「是什么、为什么、怎么用、会错在哪」。

### 可选：`cheatsheet.json` / `compare.json` / `supplement.json`

- 速查表：`[{h, formulas[], table?, bullets[], wide?}]`
- 对比表：`{meta:{qx,ng}, summary, rows:[{cat,topic,ng,qx,status(full|partial|missing),note,suppl?}]}`
- 补充：`{intro, sections:[{id,title,from,intro,concepts:[同知识卡]}]}`
- 学习记录：`{syncedAt, source, entries:[{no,date,time,title,detail,watched,progress,duration}], summary, finishedAt}`

## 五、构建与质量门禁

```bat
python _build/build.py                 :: 生成 data/*.js + 全部 html
python -m http.server 8787 --directory .
```

**每次发布前必须过 4 关**：

1. **内容体检**：`python 规范/内容体检.py --series series/<slug>`
   - 字段白名单、HTML 标签白名单（只允许 sub/sup/b/i/br）、无 LaTeX、图 key 存在、无重复标题；
2. **渲染体检**：用无头浏览器逐页 dump DOM，检查
   - 每页概念数 = 数据里的概念数、自测数一致；
   - 所有 `data-fig` 都渲染出 `<svg>`，无「示意图加载失败」；
   - 内部链接无死链（epXX.html、cheatsheet.html、learn-log.html 都存在）；
3. **截图体检**：桌面 1440px、手机 500px、深色模式各截一张，检查排版不溢出；
4. **线上验证**：push 后等 Pages 部署完成，`curl` 关键页面 200，并截一张线上图。

## 六、发布流程

1. **按课程顺序提交**，一集或一组一集：
   ```
   feat(<slug>): 第 1 集 + 框架
   feat(<slug>): 第 2–5 集
   …
   feat(<slug>): 速查表 + 学习记录
   feat(blog): 接入导航与学习笔记
   ```
2. 推送到 `grytg7yfy4-dotcom/LHHHHHH`（Pages 源：main 分支根目录）。
3. 等 GitHub Actions「pages build and deployment」成功，再访问站点验证。
4. **缓存**：构建给所有 css/js 加了 `?v=时间戳`，更新后浏览器会自动拿新文件；如果用户仍看到旧版，`Ctrl + F5` 强刷一次。

## 七、学习记录（B 站）

- 页面：`learn-log.html`，数据在 `data/learnlog.js`；
- 同步：`工具/同步B站学习记录.py`（需要 B 站 SESSDATA，只读观看历史）；
- 规则：B 站历史 `progress = -1` 表示已看完；进度 ≥85% 记为已学完；
- 手动确认：换设备/连播没同步导致进度停在开头的，可在 `learnlog.json` 里加 `"confirmed": "日期"`，页面会用 `*` 标注；
- 完结：15/15 时自动显示「课程已完结」徽章。

---

## 八、对比表与知识点补充（推荐做）

- **对比表**解决「这个系列比完整课程少了什么」：按参考课程章节逐知识点标 full/partial/missing，missing 的直接给「去补充」。
- **补充页**只放「本系列没讲或只讲一半」的内容，按参考课程章节组织，每张卡注明出处；不要整本照搬参考课程。
- 对比对象写进 `meta.ui`（`qxName` / `refName` / `compareTitle` / `suppTitle`），换系列不用改代码。
